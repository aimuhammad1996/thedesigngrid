# CLAUDE.md

## Project
Redesign and rebuild my personal portfolio website as a premium, strategic, production-grade portfolio for Muhammad Shahid, a Senior Product Designer based in Toronto, Canada.

This file is the persistent project memory and master brief for all work on this codebase.
Read this file before making any design, copy, architecture, or implementation decisions.

The final website must feel custom, art directed, high-trust, and clearly more refined than a typical product designer portfolio.
It must preserve the serious professional identity and brand equity of my current site while evolving it with stronger composition, curation, visual rhythm, and portfolio storytelling inspired by michaelbertoni.com.

## Objective
Create a portfolio website that immediately positions me as a senior systems-level product designer who can handle:
- regulated financial products
- enterprise workflows
- internal tools
- startup products
- complex user journeys
- high-stakes UX problems
- design systems and platform thinking

The website should convert:
- recruiters
- hiring managers
- design leaders
- product leaders
- startup founders
- potential clients

The core desired reaction is:
This designer can lead serious product work, think strategically, design at systems level, and execute with premium craft.

## Visual system requirements
The visual system should be built by first extracting the actual design language from my current site.

You must audit:
- colors
- typography
- spacing
- border radius
- shadows
- layout density
- component styling
- card rules
- CTA hierarchy

Then decide:
- which tokens are brand equity worth preserving
- which are accidents worth discarding
- which should be refined

Color rules:
- preserve my current color DNA
- refine, do not replace
- keep palette restrained
- avoid introducing unrelated brand colors
- do not use generic blue-purple AI aesthetics

Typography rules:
- typography should become one of the strongest parts of the redesign
- preserve the seriousness of the current typography direction
- if introducing a new pairing, it must feel like an evolution of my current brand, not a random departure
- hierarchy should feel controlled, editorial, and premium

Layout rules:
- use strong grid logic
- allow for selected moments of asymmetry
- vary section pacing
- avoid repetitive section rhythm
- avoid repeating identical card grids unless necessary
- create visual breathing room without feeling empty

Portfolio presentation rules:
- work must feel curated
- featured projects should not all look mechanically identical
- project framing should feel more strategic than decorative
- the site should feel portfolio-led, not copy-led, but copy must still support conversion

## Anti-patterns
Never do any of the following:
- glowing blob backgrounds
- purple-blue gradient AI visuals
- generic centered hero with two buttons and no composition
- three identical feature cards with icons in circles
- repetitive bento blocks with no narrative
- visual noise for the sake of personality
- weak thumbnail grids
- stock-portfolio placeholders
- excessive blur or glassmorphism
- meaningless motion
- random geometric decoration
- overuse of cards where simple layout is better
- agency-style fake authority language
- giant copy blocks with no rhythm
- a page that looks like every other designer portfolio in 2026

Choose the implementation path that gives the strongest result with the least fragility.

Preferred order:
1. Next.js
2. React + Vite
3. Static HTML/CSS/JS

Do not choose complexity for its own sake.
Do not choose a stack that weakens polish or maintainability.

## Engineering standards
- semantic HTML
- accessible structure
